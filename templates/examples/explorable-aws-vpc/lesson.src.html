Inside an AWS VPC

The big idea

A subnet is public only if its route table leads to an internet gateway; private instances go out through NAT.

You will be able to: trace a web request and a package update through a VPC, and predict which missing route breaks which flow.

Your website runs on an EC2 instance that has no public IP address. Visitors still reach it through a load balancer, and the instance still downloads updates. Press step 1 below and follow one packet each way.

Route entryTableWhat it does
10.0.0.0/16 → localbothKeeps traffic inside the VPC: ALB to instance, instance to ALB, NAT to instance.
0.0.0.0/0 → igw-0a1bpublicSends everything else to the internet gateway. This entry makes a subnet public.
0.0.0.0/0 → nat-0c9dprivateSends internet-bound traffic to the NAT gateway. Connections can only start from inside.

The ALB and the NAT gateway both sit in the public subnet, so they share one route table. One entry in it therefore carries two jobs.

You might thinkActually
A public IP makes a subnet public.A route to an internet gateway does. Without it, an instance with a public IP is still cut off.
Private instances cannot reach the internet.They can, through NAT. They just cannot be reached first.
The NAT gateway belongs in the private subnet.It sits in a public subnet with an Elastic IP, because it forwards to the internet gateway.
